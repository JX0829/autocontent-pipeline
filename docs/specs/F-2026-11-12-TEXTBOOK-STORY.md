## 1. 背景与目标

### 1.1 背景
我们已有「热点 → 短视频 → 三平台发布」的自动化流水线，单条成片 25~35 秒、科技资讯调性、双模态（1080×1920 / 1920×1080）。
现要扩展一个新内容品类：**小学语文课文背后的故事**——一篇诗/文写作时的作者处境、时代背景、文本含义，做成 90~150 秒的叙事短片。

### 1.2 目标（可度量）
- G1：单篇课文能产出 90~150 秒成片，结构完整（钩子→原诗→作者→时代→回扣→落点）
- G2：史实错误率 = 0（发布前强制人工核对，宁缺毋滥）
- G3：单篇生产人工耗时 ≤ 45 分钟（不含渲染等待）
- G4：MVP 5 篇跑通后，完播率 ≥ 35%、平均观看 ≥ 45 秒

### 1.3 非目标（本期不做）
- ❌ 不做现代文/文言文课文（先只做古诗，验证模型后再扩）
- ❌ 不做 AI 插画（V2 再上，MVP 用文字 + 公有领域素材）
- ❌ 不做自动选题（篇目由 PM 人工选定）
- ❌ 不接入教材版权内容库（课文原文短引用，注明版本）
- ❌ 不改动现有速报链路的任何行为

## 2. 用户与场景

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 家长 | 陪孩子预习/复习课文 | 孩子愿意看、知识点对 |
| 小学生（8-12 岁） | 自己刷到 | 不枯燥、看得懂 |
| 语文老师 | 课堂导入 | 史实严谨、可引用 |

主攻：家长 + 小学生；老师为口碑扩散人群。

## 4. 职责切分（RACI）

> 原则：**产品管「讲什么、讲得对不对」，技术管「怎么讲出来、稳不稳」，审核管「能不能发」。**

| 环节 | 小品（PM） | 小开（开发） | 小何（技术审核） | 小果（学习分析） | 小佳（协调） |
|---|---|---|---|---|---|
| 选题与篇目确定 | **R/A** | I | I | C | I |
| 史实考据（事实卡） | **R** | I | I | **A（教育口径）** | I |
| 故事脚本/文案 | **R/A** | I | I | C | I |
| 分镜 schema 扩展 | C | **R** | **A（评审）** | I | I |
| 古风视觉模板 | C（给设计要求） | **R** | **A（评审）** | I | I |
| TTS 音色与语速 | **A（听感验收）** | **R** | C | I | I |
| 渲染与产物 | I | **R** | **A** | I | I |
| 事实核对闸门 | **R（核对并签署）** | C（实现闸门） | C | **C（第二双眼睛）** | I |
| 发布与平台适配 | **R/A（执行）** | C | I | I | I |
| 排期与跨角色协调 | C | I | I | I | **R/A** |
| 数据回收与迭代 | **R** | I | I | C | **A** |

图例：R=执行 A=最终负责 C=需咨询 I=需知会

**边界声明**：
- 小品**不写代码、不改流水线**；技术实现全部由小开落地，小何评审。
- 小开**不改文案与史实**；内容准确性由小品与小果负责。
- 任何一方认为对方环节不达标，走「打回 + 写明原因」，不自行越界修改。

## 5. 数据契约（物料 schema 新增）

现有物料字段（`materials/*.json`）沿用，新增课文类专属块：

```json
{
  "content_type": "textbook_story",
  "title": "陆游临终前写的28个字",
  "source_url": "https://...",
  "textbook": {
    "poem_title": "示儿",
    "dynasty": "宋",
    "author": "陆游",
    "grade": "五年级",
    "volume": "上册",
    "edition": "部编版",
    "full_text": "死去元知万事空，但悲不见九州同。王师北定中原日，家祭无忘告乃翁。"
  },
  "facts": [
    {"claim": "陆游生于1125年，卒于1210年", "source": "《宋史·陆游传》", "confidence": "high"},
    {"claim": "《示儿》作于嘉定二年（1209）临终前", "source": "钱仲联《剑南诗稿校注》", "confidence": "high"}
  ],
  "storyboard_hint": {"target_duration_sec": 120, "scene_count": 16},
  "compliance": {"ai_generated_label": true, "textbook_attribution": "部编版小学语文五年级上册"}
}
```

**校验规则（技术实现）**：
- `content_type == "textbook_story"` 时：`textbook` 与 `facts` 必填，`facts` 至少 3 条且每条有 `source`
- 任一 `facts[].source` 为空 → 物料校验失败，不允许进入渲染
- `poem_title`/`author`/`dynasty` 为空 → 失败
- 现有科技类物料不受影响（`content_type` 缺省视为 `tech_news`）

## 11. Demo 验证结果（2026-11-12，分支 `feature/textbook-story`）

### 11.1 验证方式
用**现有流水线**跑通一篇课文，不做任何代码改动，目的是量化「现有能力能做到什么程度、差在哪」。

```bash
# 物料
materials/20261112_textbook_shier.json   # 《示儿》陆游，body 234 字，4 条带出处 facts
# 出片
bash scripts/verify_all.sh --fast        # VERIFY PASS
DISPATCH_MODE=output_only APPROVAL_MODE=cli APPROVAL_NONINTERACTIVE=approve \
  python3.14 -m src.pipeline.runner --material materials/20261112_textbook_shier.json --run-id shier-demo
# 结果：EXIT=0
# 产物：output/20261112/shier-demo/{video.mp4, video_16_9.mp4, cover*.png}
```

### 11.2 实测结果

| 指标 | 目标 | 实际 | 结论 |
|---|---|---|---|
| 成片时长 | 90~150s | **29.13s** | ❌ 差 3 倍 |
| 分镜数 | 12~25 | **4**（上限 8，实际只用 4） | ❌ 结构撑不住故事 |
| 旁白字数 | 400+ | **136** | ❌ LLM 自动压缩 |
| 双模态 | 1080×1920 / 1920×1080 | ✅ 均 29.13s、音轨齐备 | ✅ 复用成功 |
| 事实准确性 | facts 全部有出处 | ✅ 年份、人物、事件均对 | ✅ 内容路线可行 |
| 物料校验 | `ok: true` | ✅ `has_source_url: true` | ✅ 新增字段不破坏校验 |

### 11.3 关键发现（4 个必须解决的缺口）

1. **时长不可控**：`storyboard_hint.target_duration_sec=90` 被 LLM 完全忽略，产出 29s。
   → 需要：目标时长写进 prompt + 按旁白字数反推镜数 + 出片后时长断言（低于目标 N% 直接失败重做）。
2. **分镜数远低于上限**：schema 允许 8 镜，但 LLM 只生成 4 镜。
   → 需要：课文类 prompt 显式要求「镜数 = 目标时长 / 单镜 8~10 秒」。
3. **视觉完全不适配**：本片自动选择了 `terminal_code`（代码终端）、`stat_chart`（数据图表）、`ui_card` 三种科技风视觉——**古诗用了代码终端**。
   → 需要：课文类专属 `visual_type` 集合（水墨标题、竖排原文、古地图、卷轴转场、史料卡）。
4. **无 edu 账号类型**：`src/schemas.py:34` `target_account_type` 仅 `Literal["tech","news"]`，demo 只能借用 `tech`。
   → 需要：新增 `edu`，并在 `config/accounts.yaml` 配对应发布账号。

### 11.4 结论
**内容路线成立，工程缺口明确。** 现有链路能产出「事实准确、语气合适、双模态合规」的课文短片，但**时长、分镜、视觉三件套必须改造**才能达到 90~150 秒故事片标准。改造范围即 M1~M3，无需推翻重来。
